# 工作包完成档案索引

本目录保存每个 Day 工作包的独立完成事实。计划文档说明“准备做什么”，完成档案说明“实际做了什么、如何验证、还有什么未完成”；两者不得互相替代，也不得通过回写计划正文伪装完成状态。

## 归档规则

- 每个 Day 完成后单独新增一份 `dayN-completion-YYYY-MM-DD.md`；不得把多个 Day 合并成一份完成报告。
- 已有历史文件名保持不变，避免破坏引用。Day1 的 `day1-final-review-2026-07-15.md` 视为 Day1 独立完成档案。
- 同一 Day 需要补充复核时优先新增带日期或 review 后缀的档案，并在本索引中标明先后关系；不得覆盖旧事实。
- 档案必须链接原计划，但不修改原计划的任务结构或用计划文字充当完成证据。
- 档案只记录可复核事实；未知、未运行、部分完成和后续依赖必须明确标记，不能写成已完成。
- 代码提交前更新档案中的最终命令、测试数量、关键 hash、commit 和生成物边界；若提交 hash 只能在提交后取得，可追加一个只含 commit 对应关系的复核记录。

每份档案至少包含：

1. 原计划与本次范围；
2. 逐项完成/部分完成/未完成映射；
3. 关键实现和安全边界；
4. 验证命令、退出码及可核对结果；
5. Git commit 或明确的待提交状态；
6. 生成物、数据、hash 与忽略边界；
7. 残余风险、Inconclusive 项和后续工作包依赖；
8. 不得外推的能力声明。

新档案从 [完成档案模板](day-completion-template.md) 开始填写。
